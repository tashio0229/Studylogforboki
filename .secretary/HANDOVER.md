## 3. 記録プロトコル（exercise-log.md の書き方）

### テーブル形式（8列・厳守）
```
| 問題番号 | タイトル | 科目 | 理解度 | 解いた日 | 次回復習日 | 復習回数 | メモ |
```
- **問題番号（タグ規則）**:
  - `T##-例N` … 工原**テキスト例題**。**## は CPA 講義番号（章番号ではない！）**。例: `T17` は第13章 標準原価計算、`T20` は第15章 CVP、`T26` は第19章 意思決定会計Ⅱ。章は「科目」列に書く。
  - `P##-…` … 工原**問題集**。
  - `C##-例N` … 商業/会計**例題**。**## は章番号**（例: `C24` = 第24章 収益認識、`C25` = 第25章 本支店）。
- **科目**列: `工業 #NN 章名` または `商業 第NN章 章名`。ダッシュボードの記録フォームは subject 値 `工業` / `商業` と一致必須。
- **日付**: `YYYY-MM-DD`。**必ず実際の学習日（`date` コマンドで当日を確認）**。深夜をまたぐ学習でも「その学習の暦日」で記録。
- **メモ**: 遷移履歴を追記（例: `初回△(7/15)→△継続(7/17)`）。上書きせず、`→…(M/D)` を足していく。

### 復習間隔ルール（exercise-log.md 冒頭が正典）
- **✕** = +1日固定（△になるまで毎日）
- **△** = +2日固定（回数で伸ばさない。**4回目以降=「要対策△」**フラグ→間隔を空けず介入を1回挟む：講義戻り／解答手順の書き出し）
- **○** = +7日 → +14日 → +30日 → 終了
- **昇格リセット**: ✕→△ は △第1回(+2)へ、△→○ も同様。**降格**: △中に✕なら✕ルールへ。
- **新規（1周目）を△で記録する場合**: 解いた日=当日、次回復習日=当日+2、復習回数=1。
- **1日の処理順**: ✕全問 → 期限切れ△（古い順）→ 当日△ → 新規例題。
- **○の"真の○"観**（本人談）: ○は3回転連続○で初めて真の○。ただし○維持の復習コストは軽い。降格を責めず「軽いコストで効く」と位置づける。

### 記録の実務（安全な一括追記）
16問など複数を一括記録する時は、手編集ではなく**Python スクリプトで追記→8列整合を検証**する（前任はこの方式）。副題は必ず**PDF実物**から取る（§6）。プレースホルダ副題は禁止。ユーザーは「ちゃんと副題も残して」と明示的に要求している。

### 記録したら必ず Vault 再生成（§後述）
`exercise-log.md` を変更したら `python3 tools/generate_vault_views.py` を実行（`問題ノート/` 配下に個別ノートを再生成）。

## 4. ダッシュボードの更新手順（dashboard.html）

### 基本
- `dashboard.html` は自己完結の単一 HTML。**編集するのは `const DATA = {…}` オブジェクトだけ**。JS が `new Date()` からカウントダウン等を動的計算する。
- 主なキー: `meta`（updated/examDate/phaseA…）, `directive`（今日の指令）, `todayQueue`（今日のキュー）, `cards`, `stats`（recorded/o/d/x/needAction/subjects）, `recentWins`, `weekPlan`, `reviewQueue`, `phases`。
- **`todayQueue` の各要素**: `{ subject:"商業"|"工業", chapter:"第NN章 …", example:"例N", subtitle:"副題", note:"…" }`。記録済みの問題はキューから外す。
- **編集後は必ず構文検証**（前任の方法）:
  ```bash
  node -e 'const s=require("fs").readFileSync(".secretary/study/dashboard.html","utf8");
    const m=s.match(/const DATA = (\{[\s\S]*?\n\});/); const DATA=eval("("+m[1]+")");
    console.log(DATA.stats, DATA.todayQueue.length);'
  ```
  文字列内に生の ASCII ダブルクォート `"` を入れない（JS が壊れる。全角『』や別語に置換）。

### ★ Claude 固有の制約（Codex では引き継げない部分）
- 前任はダッシュボードを **claude.ai の Artifact（共有リンク）** として発行していた:

  そのための body-only 版 `dashboard-artifact.html`（`<style>` + `<body>`内側のみ）を生成し、`Artifact` ツールで同 URL に再発行していた。
- **この Artifact 発行/再発行は Claude Code 専用ツール**。Codex（OpenAI）にはこのツールが無いため、**同じ共有リンクの更新はできない**。
- Codex での現実的な運用（いずれか）:
  1. **`dashboard.html` を直接ブラウザで開いて見る**（自己完結なのでファイルを開けば動く）。共有リンクは諦める。

- 工原 問題集: `…工原+問題集.pdf`

抽出手順（前任の方法）:
```bash
# テキスト化（レイアウト保持）。日本語フォントが要る場合:
#   apt-get install -y poppler-utils poppler-data fonts-noto-cjk
pdftotext -layout "<PDF>" out.txt
grep -nE "例 *題" out.txt        # 「例題N 副題  重要度X」の行を拾う
# pypdf を使う場合は cffi が必要: pip install cffi pypdf
```
CPA 教材は各例題に**重要度 A/B/C** が付く。記録メモに重要度を残すと後で優先度判断に使える。
