# lessons/ — 学び（メモリ）システム

秘書が過去の運用から得た**学び・修正・うまくいった型**を蓄積し、次に活かすための場所。
Claude Fable 5 運用ガイドの「メモリシステムの構築」推奨をこの秘書システムに適用したもの。

## 書き方のルール

- **1ファイル1件**。ファイル名は `descriptive-kebab-case.md`（例: `report-per-lecture-beats-youtube.md`）。
- **先頭に1行サマリー**（`# ...`）。ここだけ読めば何の学びか分かるようにする。
- **修正も、確認済みの成功パターンも両方残す**。「これが効いた」「これは効かなかった」の両方が価値。
- **なぜ重要かを必ず書く**。理由が残っていないと、後で判断がぶれる。

## やってはいけないこと

- **既に記録済みのことを重複させない**。`.secretary/CLAUDE.md` の「観察済みの行動パターン」やチャット履歴に既にあることは、ここに二重で書かない。
- **重複ファイルを作らない**。同じテーマの学びが既にあれば、新規作成せず**既存ファイルを更新**する（`updated:` を更新）。
- **間違いと分かった学びは消す**（または `status: deprecated` にして理由を残す）。古い誤った学びを残すと判断を誤らせる。

## 秘書側の使い方

- セッション開始時、`CLAUDE.md` に加えて `lessons/` の既存ノート（特に `status: confirmed`）にも目を通し、過去の学びを踏まえて対応する。
- 「これはうまくいった／今回はこれで失敗した」と分かったら、その場で1件記録する（クイックコマンド: `学び記録 [内容]`）。
- カテゴリの目安: `study`（簿記1級）/ `training`（マラソン）/ `work`（経理業務）/ `meta`（秘書の動き方そのもの）。
